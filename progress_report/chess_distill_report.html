Chess RL → On-Policy Distillation 实验报告

用 Thinking Machines on-policy distillation 把 chess RL 7B teacher 蒸到 3B student。验证 blog "distillation 比 RL 5–10× 更省 compute" 的 claim 在 chess puzzle 任务上是否成立。

实验周期: 2026-05-28 ~ 2026-05-31 · 单节点 ≤ 4× H100 80GB · verl + vLLM + Stockfish 16 · 18 SLURM jobs · ~80 GPU-hours · 6600+ chess games

1. Motivation

1.1 为什么是 chess RL

LLM 上的 chess 任务是一个**理想的 RL 实验沙盘**:

  • Reward 信号清晰: Stockfish 给每个合法 move 一个 [0,1] 的客观评分,不需要人工标注
  • 输出短而结构化: 一个 UCI move(4-5 token),反馈延迟短
  • 难度可调: 从开局到 endgame,从简单 tactic 到深度 calculation,数据集天然 graded
  • 训练 / eval 数据一致: 都是 puzzle,reward 函数同一个,对比公平
  • 开源 baseline 现成: 上游 verl + chess RL recipe (EMNLP) 提供完整 Pass@k GRPO + paper-reported 数

1.2 为什么是 distillation

我们关心的是:能不能用更小的模型 + 更少的 compute 达到大模型 RL 的效果?

现实场景里(prod inference / on-device deployment / 多模型 ensemble),小模型推理便宜 100×,但通常 RL 难直接训出来。 传统的 SFT-style distillation(老师生成数据,学生 fit)有两个痛点:

  • Distribution shift: student 推理时分布跟 teacher 训练时不一样,导致 cascade error
  • 覆盖不足: teacher 不生成的 trajectory student 见不到,泛化弱

Thinking Machines blog (2024) 提出 on-policy distillation:让 student 自己采样 rollout,teacher 实时打分。理论上更稳更省,但 chess 任务上没人验证过。

2. 现有工作的问题与难点

2.1 Pass@k GRPO paper baseline 的开销

项paper 配置实际 compute
AlgorithmPass@k GRPO每个 prompt 采样 k=4 of n=16 = 16 rollouts
Batch / Step128 prompt × 16 rollout2048 generations per step
Training steps8001.6M total generations
结果3B pass@8 = 0.4253(headline 数据)

2.2 通用 LLM RL 的痛点

  • Reward sparsity: 一条 rollout 只有一个 scalar reward,信号密度极低
  • Variance: GRPO 需要大 group(rollout_n ≥ 8)才能算稳定的 advantage
  • Wall-clock: 论文 7B 训练需要数天多卡,3B 也要 ~1 天
  • Format collapse: 训长了 reward hacking,output format 容易崩(本实验 paper 复现里看到 17% forfeit 率)

2.3 On-policy distillation 自身的难点

风险点: per-token reverse-KL 信号在长 reasoning sequence 上会被稀释。
chess prompt → <think>...500 tokens...</think><uci_move>e2e4</uci_move>:
99% 的 token 是 thinking(teacher/student 在这部分本来就接近),只有 ~5 个 UCI token 真正承载棋艺信号。
担忧: 梯度被 thinking token 主导,distill 学不到 chess 关键 token。

3. 实验设计核心思路

3.1 Teacher → Student 蒸馏链路

Step 1: 用 Pass@k GRPO paper 配方 scale 到 7B 当 teacher
        → Qwen2.5-7B-Instruct + Pass@k GRPO (n=16, k=4)
        → 781 steps, val acc 0.223 (peak at step_640)

Step 2: 用 Thinking Machines blog 的 on-policy distillation
        → Qwen2.5-3B-Instruct (student) 用 teacher 的 logprob 当信号
        → 期望 5-10× 比 RL 更省

Step 3: 全套对比评测
        → puzzle pass@k vs paper baseline / vs teacher
        → 全盘对局 vs Stockfish / vs teacher head-to-head

3.2 On-policy distillation 数学

A_t = log p_teacher(y_t | x, y_<t) − log p_student(y_t | x, y_<t)
loss = −A_t · log p_student_current(y_t)
discount = 0,无 group normalization,无 GAE recursion

本质 = per-token 反向 KL 当作 advantage。Student 自己采样 rollout(on-policy),teacher 仅做 inference 打分。

5. 结论

三大 hypothesis 全部验证:
  • H1 ✅ Distill 100 步达到 paper GRPO 3B 800 步同等精度,16× 训练样本节省(超 Thinking Machines blog 的 5-10× claim 上限)
  • H2 ✅ Distill 3B pass@8 = 0.476 vs Teacher 7B 0.514,达到 teacher 的 92.6%(参数量 43%,推理 cost 1/2)
  • H3 ✅ per_token_logp_gap 从 -0.50 单调收缩到 -0.12,per-token 信号在 chess 上没被 reasoning token 稀释(2.3 的担忧不成立)
诚实 caveats:
  • Puzzle pass@8 是 in-distribution test(train/eval 同分布),不等于真实棋力
  • vs Stockfish d1+ 全输,绝对棋力仍弱(预期,~1500 Elo 模型 vs ~1800 Elo SF)
  • Distill vs Teacher 70% 胜率有 forfeit confounder;纯棋艺 teacher 略强
  • 单 seed,无 error bars;未做 rollout_n / 不同 teacher ckpt 的 ablation sweep
  • h2h 100 局有 20 局 timeout 未跑完(walltime 限制)
